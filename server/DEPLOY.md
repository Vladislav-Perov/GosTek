# Пошаговое руководство по настройке Cloudflare Worker для GosTek

> Данная инструкция написана простым языком и содержит пошаговый алгоритм действий в формате **«нажми на <название>»** без пропусков. Настройка занимает около 5–7 минут.

---

## 1. Пошаговое развертывание кода через веб-интерфейс Cloudflare

Для развертывания не требуется устанавливать Node.js, Git или консольные утилиты. Все действия выполняются прямо в браузере.

### Шаг 1. Открытие панели управления
1. Открой сайт [dash.cloudflare.com](https://dash.cloudflare.com/) и войди в свой аккаунт.
2. В левом вертикальном меню нажми на **Workers & Pages** (в некоторых версиях интерфейса раздел называется **Compute (Workers)**).

### Шаг 2. Выбор или создание воркера
1. Если воркер с именем **gostek-proxy** уже есть в списке:
   - Нажми на имя воркера **gostek-proxy**.
2. Если воркера ещё нет:
   - Нажми на синюю кнопку **Create application** (или **Create Worker**).
   - В поле имени введи `gostek-proxy`.
   - Внизу нажми на кнопку **Deploy**.
   - На открывшейся странице нажми на ссылку **Configure Worker** или вернись в **Workers & Pages** и нажми на **gostek-proxy**.

### Шаг 3. Редактирование кода воркера
1. На странице воркера в правом верхнем углу нажми на кнопку **Edit code** (откроется встроенный редактор кода Cloudflare).
2. В левой колонке файлов убедись, что выбран файл `worker.js`.
3. Кликни левой кнопкой мыши внутри окна с кодом.
4. Нажми сочетание клавиш `Ctrl + A` (выделить всё).
5. Нажми клавишу `Delete` (или `Backspace`), чтобы полностью очистить окно редактора.
6. Открой файл [server/worker.js](file:///d:/-GosTek_WORK-/GosTek/server/worker.js) из проекта GosTek, скопируй весь его текст (`Ctrl + A`, затем `Ctrl + C`).
7. Вернись в браузер и вставь скопированный код в пустое окно редактора (`Ctrl + V`).
8. В правом верхнем углу редактора нажми на синюю кнопку **Deploy**.
9. Дождись появления всплывающего уведомления внизу экрана: *«Deployed successfully»*.
10. В левом верхнем углу редактора нажми на стрелку назад **←** (или на название воркера), чтобы вернуться на страницу настроек.

## 2. Настройка переменных окружения и секретных ключей (Variables and Secrets)

После сохранения кода необходимо добавить API-ключи провайдеров нейросетей.

### Шаг 4. Переход в раздел переменных
1. В верхнем горизонтальном меню воркера нажми на вкладку **Settings**.
2. В левом меню раздела Settings нажми на пункт **Variables and Secrets** (в некоторых аккаунтах пункт называется **Variables**).

### Шаг 5. Добавление каждой переменной
Для каждой переменной из таблицы ниже выполни следующие шаги:
1. В блоке **Environment Variables** нажми на кнопку **Add variable** (или кнопку **Add**).
2. В поле **Variable name** введи точное имя переменной (например, `GEMINI_API_KEY`).
3. В поле **Value** вставь значение (твой API-ключ или имя модели).
4. **ВАЖНО для API-ключей:** если переменная является секретом (колонка *Тип* = *Secret*), нажми на кнопку **Encrypt** рядом с полем значения. Значение станет зашифрованным и скроется звёздочками.
5. Для текстовых параметров (колонка *Тип* = *Text*, например `GEMINI_MODEL`) нажимать *Encrypt* не нужно.
6. Нажми на кнопку **Save and Deploy** (или **Deploy**) внизу формы, чтобы изменения вступили в силу.

## 3. Таблица всех переменных окружения

| Имя переменной | Тип | Обязательна? | Пример значения | Где получить значение |
|:---|:---:|:---:|:---|:---|
| **`GEMINI_API_KEY`** | **Secret** (Encrypt) | **Да** (основная модель) | `AIzaSyD-xxxxxxxxxxxx` | Открой [Google AI Studio: API Keys](https://aistudio.google.com/app/apikey) → нажми на синюю кнопку **Create API key** → скопируй выданный ключ. |
| **`GEMINI_MODEL`** | **Text** (обычная) | Нет (по умолчанию `gemini-2.0-flash`) | `gemini-2.0-flash` | Указывает идентификатор модели Google. См. раздел 4 для получения списка поддерживаемых моделей. |
| **`GROQ_API_KEY`** | **Secret** (Encrypt) | Нет (резервный fallback) | `gsk_xxxxxxxxxxxxxxxx` | Открой [Groq Console: API Keys](https://console.groq.com/keys) → нажми на кнопку **Create API Key** → скопируй ключ. |
| **`DEEPSEEK_API_KEY`** | **Secret** (Encrypt) | Нет (резервный fallback) | `sk-xxxxxxxxxxxxxxxx` | Открой [DeepSeek Platform: API Keys](https://platform.deepseek.com/api_keys) → нажми на кнопку **Create API Key** → скопируй ключ. |
| **`MODELS_CASCADE`** | **Text** (обычная) | Нет (каскад строится автоматически) | `[{"provider":"gemini","model":"gemini-2.0-flash"},{"provider":"groq","model":"llama-3.1-8b-instant"}]` | Ручная настройка цепочки моделей в формате JSON. Если не задана, воркер сам пробует Gemini, затем DeepSeek, затем Groq. |

> [!TIP]
> Достаточно добавить хотя бы один ключ — `GEMINI_API_KEY`. Воркер сразу начнёт полноценно обрабатывать запросы. Добавление `GROQ_API_KEY` рекомендуется как бесплатная подстраховка на случай сбоев или исчерпания суточных лимитов Google.

## 4. Как узнать актуальный список моделей Google (ListModels) и выбрать модель

В коде воркера имена моделей Google не зашиты жестко: воркер использует переменную `GEMINI_MODEL`, а если она не задана — проверенную стабильную модель по умолчанию `gemini-2.0-flash`.

### Что важно знать об именах моделей Gemini
Ранее ходили слухи о версии «Gemini 2.5», однако в официальном публичном API Google Gemini (по состоянию на начало 2026 года) доступны поколения **Gemini 2.0** (`gemini-2.0-flash`, `gemini-2.0-flash-lite-preview-02-05`) и **Gemini 1.5** (`gemini-1.5-flash`, `gemini-1.5-pro`). Несуществующие идентификаторы (например, `gemini-2.5-flash-lite`) вызывают от Google ошибку HTTP 404 (*models/gemini-2.5-flash-lite is not found*).

### Команда PowerShell для получения актуального списка моделей твоего аккаунта
Открой PowerShell на своём компьютере, подставь свой API-ключ Gemini и выполни:

```powershell
$apiKey = "ВСТАВЬ_СЮДА_СВОЙ_GEMINI_API_KEY"
$res = Invoke-RestMethod -Uri "https://generativelanguage.googleapis.com/v1beta/models?key=$apiKey" -Method Get
$res.models | Where-Object { $_.supportedGenerationMethods -contains "generateContent" } | Select-Object @{Name="Имя модели для GEMINI_MODEL"; Expression={$_.name -replace "^models/", ""}}, displayName | Format-Table -AutoSize
```

### Как выбрать модель:
1. Посмотри в колонку **Имя модели для GEMINI_MODEL**.
2. Выбери быструю и эффективную модель для чата:
   - `gemini-2.0-flash` — **рекомендуемый выбор** (максимальная скорость, отличное понимание официального стиля).
   - `gemini-2.0-flash-lite-preview-02-05` — суперлёгкая и быстрая модель с минимальным потреблением квоты.
   - `gemini-1.5-flash` — проверенная стабильная рабочая лошадка.
3. Скопируй выбранное имя (например, `gemini-2.0-flash`) и вставь его в Cloudflare в переменную **`GEMINI_MODEL`** (Text).

## 5. Проверка работоспособности воркера через PowerShell

После развертывания кода и добавления секретов проверь работу сервера одной командой.

### Команда проверки через curl.exe (PowerShell)
Замени `<твой-субдомен>` на имя своего поддомена Cloudflare (его видно на главной странице воркера под заголовком):

```powershell
curl.exe -X POST "https://gostek-proxy.<твой-субдомен>.workers.dev" `
  -H "Content-Type: application/json" `
  -d '{\"userText\": \"проспал работу\", \"templateName\": \"Объяснительная записка\", \"fieldsContext\": \"Текущее состояние полей: [ФИО: [ФИО_1], Причина: [пусто]]\"}'
```

### Точный ожидаемый ответ (HTTP 200 OK):
```json
{
  "success": true,
  "data": {
    "fields": {
      "Причина": "Опоздал на рабочее место в связи с непредвиденными личными обстоятельствами (проспал)."
    },
    "question": null,
    "status": "success"
  },
  "memory_ops": [],
  "text": "{\"fields\":{\"Причина\":\"Опоздал на рабочее место в связи с непредвиденными личными обстоятельствами (проспал).\"},\"question\":null}",

```

## 6. Таблица типичных ошибок и способов их решения

| Код ошибки | Сообщение / Симптом | Причина | Что сделать (пошагово) |
|:---:|:---|:---|:---|
| **401** | `Unauthorized` | Неверный или удалённый API-ключ | 1. Зайди на [Google AI Studio](https://aistudio.google.com/app/apikey).<br>2. Создай новый API-ключ.<br>3. В Cloudflare Settings → Variables and Secrets нажми Edit у `GEMINI_API_KEY`, вставь новый ключ, нажми Encrypt и Save and Deploy. |
| **403** | `Forbidden` | Ограничение доступа по региону или WAF | 1. Google Gemini API может блокировать запросы из некоторых регионов без VPN/прокси.<br>2. Добавь в воркер запасной ключ `GROQ_API_KEY` (Groq работает без ограничений). |
| **404** | `models/... is not found` | Указано несуществующее имя модели | 1. Выполни команду из Раздела 4 для получения списка моделей.<br>2. В Cloudflare в переменной `GEMINI_MODEL` укажи валидное имя (например, `gemini-2.0-flash`). |
| **413** | `Размер запроса превышает допустимый лимит (32 КБ)` | Воркер защищает память от переполнения | Запрос клиента слишком велик. В штатном клиенте GosTek запросы занимают не более 2–4 КБ. |
| **429** | `Too Many Requests` | Исчерпан лимит запросов в минуту (RPM) у Google | На бесплатном тарифе Gemini действует лимит 15 RPM. Добавь в воркер `GROQ_API_KEY` для мгновенного автоматического fallback на Llama 3.1 8B. |
| **503** | `Сервис ИИ временно перегружен или недоступен` | Все модели в цепочке каскада завершились ошибкой или истёк таймаут 15 сек | 1. Проверь, добавлен ли хотя бы один API-ключ в Variables and Secrets.<br>2. Проверь баланс/квоту в консоли провайдера. |
| **Пустой ответ / Timeout** | Запрос висит и завершается ошибкой сети | Неверный URL воркера или воркер отключен | Проверь статус воркера в панели Cloudflare: должен гореть зелёный значок *Active*. Проверь точность URL в константе `AiAssistantService.DefaultEndpoint`. |

## 7. Как откатить воркер на предыдущую версию

Если после внесения изменений что-то сломалось, можно вернуться на прошлую работающую версию в 3 клика:

1. В левом меню Cloudflare Dashboard нажми на **Workers & Pages**.
2. В списке воркеров нажми на **gostek-proxy**.
3. В верхнем горизонтальном меню нажми на вкладку **Deployments** (или **Version History**).
4. В списке версий найди предыдущую стабильную версию по дате и времени.
5. Напротив нужной версии нажми на три точки **...** (справа).
6. В выпадающем меню нажми на **Rollback** (Откатить).
7. Во всплывающем окне подтверждения нажми на синюю кнопку **Rollback to this deployment**. Предыдущая версия активируется мгновенно.

## 8. Как включить ограничение частоты запросов (Rate Limiting) в панели Cloudflare

Ограничение защищает воркер от спама, сканирования и исчерпания бесплатных квот нейросетей:

1. В левом меню Cloudflare Dashboard нажми на раздел **Security** (Безопасность).
2. В раскрывшемся списке нажми на **WAF** (Web Application Firewall).
3. В верхних вкладках раздела WAF нажми на **Rate limiting rules**.
4. Нажми на синюю кнопку **Create rule** (Создать правило).
5. Заполни форму правила:
   - **Rule name:** введи `GosTek AI Rate Limit`.
   - **If incoming requests match:** выбери `Custom filter expression`.
   - **Field:** выбери `URI Path`.
   - **Operator:** выбери `equals`.
   - **Value:** введи `/`.
   - **With the same characteristics:** выбери `IP` (по IP-адресу пользователя).
   - **Requests:** введи `20`.
   - **Period:** выбери `1 minute`.
   - **Choose action:** выбери `Block` (Блокировать) или `Managed Challenge` (Капча при превышении).
   - **Duration:** выбери `1 minute`.
6. В правом нижнем углу нажми на кнопку **Deploy**.
7. Правило активировано: пользователи, отправляющие более 20 запросов в минуту с одного IP, будут временно отсекаться Cloudflare, не нагружая воркер и не расходуя квоту LLM.
