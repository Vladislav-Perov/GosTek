# Регламент ручной проверки приложения GosTek (MANUAL_CHECKLIST.md)

Настоящее руководство предназначено для членов экспертного жюри и комиссии конкурса. В нём приведены пошаговые сценарии демонстрации и тестирования ключевых возможностей приложения **GosTek** на Windows 10/11 и Android.

---

## Сценарий 1. Быстрый старт и проверка документа по ГОСТ

### Цель
Продемонстрировать детерминированный аудит структуры документа Word (`.docx`) через OpenXML SDK и исправление замечаний в один клик.

### Шаги проверки:
1. Запустите приложение GosTek.
2. На вкладке **«Главная»** или **«Проверка»** нажмите кнопку **«Выбрать документ для проверки»**.
3. Выберите любой файл `.docx` (или тестовый файл с нарушениями ГОСТ).
4. **Ожидаемый результат:**
   - Приложение мгновенно выполняет аудит структуры: поля страницы (левое 30 мм, правое 10 мм, верхнее/нижнее 20 мм), шрифт (Times New Roman / Calibri / Arial), кегль (12–14 pt), полуторный интервал, абзацный отступ (1.25 см), нумерация страниц.
   - Отображается детальный список замечаний с группировкой по категориям.
5. Нажмите кнопку **«Устранить замечания (N)»**.
6. **Ожидаемый результат:**
   - Создается исправленный файл с суффиксом `_gost.docx`.
   - При повторном открытии файла все замечания устранены (зеленый статус «Документ полностью соответствует ГОСТ»).

## Сценарий 2. Заполнение шаблона и централизованный ИИ-помощник

### Цель
Продемонстрировать генерацию документа по шаблону, диалог с ИИ на естественном языке и работу локального шлюза маскирования персональных данных (Outbound Gateway).

### Шаги проверки:
1. Перейдите на вкладку **«Шаблоны»**.
2. Выберите шаблон **«Заявление на отпуск»** или **«Договор подряда»**.
3. В шапке формы или по плавающей кнопке справа внизу нажмите **«ИИ-Помощник»** (откроется компактная шторка чата).
4. При первом открытии приложение запрашивает согласие на использование облачного ИИ: ознакомьтесь с предупреждением и подтвердите согласие.
5. Введите свободный текст, содержащий персональные данные:
   > *«Я, Иванов Иван Иванович, проживающий в г. Минск, ул. Ленина, д. 10, кв. 5, телефон +375291234567, паспорт МР 1234567, прошу предоставить трудовой отпуск с 1 по 14 июля 2025 года.»*
6. Нажмите кнопку **«Отправить»**.
7. **Ожидаемый результат:**
   - Перед сетевым вызовом все ПДн маскируются локально (`PrivacyMasker`): ФИО, адрес, телефон и паспорт заменяются безопасными токенами `[ФИО_1]`, `[АДРЕС_1]`, `[ТЕЛЕФОН_1]`, `[ПАСПОРТ_1]`.
   - ИИ возвращает карточку с распознанными полями формы.
   - Нажмите **«Применить к форме»**: поля формы автоматически заполняются реальными исходными данными пользователя.
   - В окне предпросмотра ГОСТ-страницы А4 отображается готовый документ.
8. Нажмите кнопку **«Собрать документ»**: выберите сохранение в Word (`.docx`) или генерацию чистого ГОСТ-документа PDF через QuestPDF.

## Сценарий 3. Сканирование паспорта РБ, ICAO 9303 MRZ и Diff-экран

### Цель
Продемонстрировать распознавание паспорта гражданина РБ с парсингом машиносчитываемой зоны MRZ (ICAO 9303) и подтверждение изменений профиля через экран сравнения (diff).

### Шаги проверки:
1. Перейдите на вкладку **«Сканирование»**.
2. Нажмите кнопку **«Галерея»** или **«Файл»** и выберите фото последней страницы паспорта РБ (с двумя строками MRZ `P<BLR...` внизу).
3. Дождитесь завершения предобработки изображения и распознавания OCR.
4. **Ожидаемый результат:**
   - В блоке результатов отображается зеленый бейдж: **«✓ ICAO 9303 MRZ проверена»**.
   - Рассчитаны и подтверждены контрольные суммы по алгоритму 7-3-1 (номер паспорта, дата рождения, срок действия, личный номер).
   - Отображается таблица сопоставления с текущим профилем:
     - ФИО: *Было: [старое значение]* ➔ *Станет: [распознанное]* + Чекбокс
     - Паспорт: *Было: [старое значение]* ➔ *Станет: [распознанное]* + Чекбокс
     - Личный номер: *Было: [старое значение]* ➔ *Станет: [14-значный номер]* + Чекбокс
5. Снимите галочку с одного из полей и нажмите **«Применить выбранные в профиль»**.
6. Перейдите на вкладку **«Профиль»**: убедитесь, что применились только отмеченные поля, а данные зашифрованы в `SecureStorage`.

## Сценарий 4. Связка OCR сканера с каталогом шаблонов

### Цель
Продемонстрировать сквозной перенос текста произвольного отсканированного документа в шаблон Word через буфер `DraftStore`.

### Шаги проверки:
1. На вкладке **«Сканирование»** переключите чип типа документа на **«Любой документ»** (или «Свидетельство»).
2. Загрузите любое фото документа с текстом.
3. В нижнем блоке «Распознанный текст» нажмите кнопку **«Перенести текст в шаблон документа...»**.
4. **Ожидаемый результат:**
   - Приложение автоматически открывает вкладку **«Шаблоны»** и выводит уведомление *«Текст готов для вставки в шаблон»*.
   - Выберите любой подходящий шаблон.
   - При открытии шаблона автоматически открывается чат ИИ с уже подготовленным текстом скана: *«Заполни поля документа по тексту: [текст скана]»*.
   - ИИ раскладывает данные скана по полям выбранного шаблона.

## Сценарий 5. Адаптивность окна, сворачивание Navigation Rail и клавиша Escape на Windows

### Цель
Продемонстрировать качество верстки на десктопной платформе Windows 10/11: корректную геометрию перетаскивания, адаптивность коридора 950px и защиту от крашей.

### Шаги проверки:
1. На Windows кликните по кнопке-тумблеру **«Свернуть/Развернуть панель»** в левом верхнем углу (над вкладками).
   - **Ожидаемый результат:** Боковая панель плавно сворачивается с 220px до компактных 64px (иконки остаются центрированными). Область перетаскивания окна мгновенно адаптируется, клики по кнопке не перехватываются перетаскиванием.
2. Попробуйте сжать окно приложения по горизонтали и вертикали до минимальных размеров.
   - **Ожидаемый результат:** Окно аппаратно удерживает минимальный размер 800x600 без искажений и вылетов (`WM_GETMINMAXINFO`).
3. Разверните окно на полный экран (1920x1080):
   - **Ожидаемый результат:** Контент всех страниц центрирован в коридоре 950px с отступами `Fill` без обрезания контента. Шторка чата открывается аккуратной панелью 490px справа.
4. Установите фокус в любое текстовое поле ввода и нажмите клавишу **Escape**:
   - **Ожидаемый результат:** Первый Escape снимает фокус с поля ввода (страница не закрывается). Второй Escape выполняет возврат назад по стеку страниц или на Главную.

## Сценарий 6. Проверка конфиденциальности и очистка данных

### Цель
Продемонстрировать гарантии приватности (Privacy by Design), локальное шифрование и функции экстренного стирания данных.

### Шаги проверки:
1. Откройте шторку **«Настройки»** (кнопка слайдеров в шапке Главной страницы).
2. Нажмите **«Очистить временные файлы»**:
   - **Ожидаемый результат:** Все временные фотографии камеры, файлы сканов и рабочие копии `.docx`/`.pdf` безвозвратно удаляются из кэша приложения.
3. Нажмите **«Удалить профиль»**:
   - **Ожидаемый результат:** Ключи профиля и сохраненные ПДн в `SecureStorage` полностью стираются.
4. Проверьте системные файлы проекта `Platforms/Android/Resources/xml/data_extraction_rules.xml` и `backup_rules.xml`:
   - Убедитесь, что закрытые директории баз данных, настроек и кэша исключены из облачных бэкапов Google.
