# Регламент ручной проверки приложения GosTek (MANUAL_CHECKLIST.md)

Настоящее руководство предназначено для членов экспертного жюри и комиссии конкурса. В нём приведены пошаговые сценарии демонстрации и тестирования ключевых возможностей приложения **GosTek** на Windows 10/11 и Android.

---

## Сценарий 1. Быстрый старт и проверка документа по ГОСТ

### Цель
Продемонстрировать детерминированный аудит структуры документа Word (`.docx`) через OpenXML SDK и исправление замечаний в один клик.

### Шаги проверки:
1. Запустите приложение GosTek.
2. На вкладке **«Главная»** или **«Проверка»** нажмите кнопку **«Выбрать документ для проверки»** (или перетащите файл в зону drag-and-drop на Windows).
3. Выберите любой файл `.docx` (или тестовый файл с нарушениями ГОСТ).
4. **Ожидаемый результат:**
   - Приложение мгновенно выполняет аудит структуры: поля страницы (левое 30 мм, правое 10 мм, верхнее/нижнее 20 мм), гарнитура шрифта (Times New Roman), кегль (12–14 pt), полуторный интервал, абзацный отступ (1.25 см), нумерация страниц, подписи таблиц, рисунков и листингов.
   - Отображается детальный список замечаний с группировкой по категориям, возможностью раскрытия и индивидуального принятия/отклонения.
5. В шапке списка замечаний нажмите кнопку **«Принять все»**.
6. Нажмите кнопку **«Сохранить копию»**.
7. **Ожидаемый результат:**
   - Создается исправленный файл с суффиксом `_gost.docx`. Исходный файл пользователя остаётся нетронутым.
   - При открытии сохранённого файла отображается зелёный статус «Все замечания устранены! Документ полностью соответствует выбранному стандарту ГОСТ».

## Сценарий 2. Заполнение шаблона и централизованный ИИ-помощник

### Цель
Продемонстрировать генерацию документа по шаблону, диалог с ИИ на естественном языке и работу локального шлюза маскирования персональных данных (Outbound Gateway) по Закону РБ № 99-З.

### Шаги проверки:
1. Перейдите на вкладку **«Шаблоны»**.
2. Выберите любой из 9 эталонных шаблонов (например, **«Заявление на отпуск»** или **«Справка с места учёбы»**).
3. В шапке формы или по плавающей кнопке справа внизу нажмите **«ИИ-Помощник»** (откроется компактная шторка чата).
4. При первом открытии приложение запрашивает согласие на использование облачного ИИ: ознакомьтесь с предупреждением и подтвердите согласие.
5. Введите свободный текст, содержащий персональные данные:
   > *«Я, Иванов Иван Иванович, проживающий в г. Минск, ул. Ленина, д. 10, кв. 5, телефон +375291234567, паспорт МР 1234567, прошу предоставить трудовой отпуск с 1 по 14 июля 2026 года.»*
6. Нажмите кнопку **«Отправить»**.
7. **Ожидаемый результат:**
   - Перед сетевым вызовом все ПДн маскируются локально (`PrivacyMasker`): ФИО, адрес, телефон и паспорт заменяются безопасными токенами `[ФИО_1]`, `[АДРЕС_1]`, `[ТЕЛЕФОН_1]`, `[ПАСПОРТ_1]`. Аппаратный барьер `AssertPayloadSafe` гарантирует невозможность утечки сырых данных в сеть.
   - ИИ возвращает карточку с распознанными полями формы.
   - Нажмите **«Применить к форме»**: поля формы автоматически заполняются реальными исходными данными пользователя.
   - В окне предпросмотра ГОСТ-страницы А4 отображается готовый документ.
8. Нажмите кнопку **«Собрать документ»**: выберите сохранение в Word (`.docx`) или генерацию чистого ГОСТ-документа PDF через QuestPDF.

## Сценарий 3. Сканирование паспорта РБ, ICAO 9303 MRZ и Diff-экран

### Цель
Продемонстрировать распознавание паспорта гражданина РБ с парсингом машиносчитываемой зоны MRZ (ICAO 9303) и подтверждение изменений профиля через экран сравнения (diff).

### Шаги проверки:
1. Перейдите на вкладку **«Сканирование»**.
2. Нажмите кнопку **«Камера»** (наведите видоискатель) или выберите фото через **«Галерея»** / **«Файл»** (последняя страница паспорта РБ с двумя строками MRZ `P<BLR...` внизу).
3. Дождитесь завершения предобработки изображения и распознавания OCR.
4. **Ожидаемый результат:**
   - В блоке результатов отображается зеленый бейдж: **«✓ ICAO 9303 MRZ проверена»**.
   - Рассчитаны и подтверждены контрольные суммы по алгоритму 7-3-1 (номер паспорта, дата рождения, срок действия, 14-значный личный номер).
   - Латинские имена автоматически транслитерированы на русский язык.
   - Отображается интерактивная таблица сопоставления с текущим профилем:
     - ФИО: *Было: [старое значение]* ➔ *Станет: [распознанное]* + Чекбокс
     - Паспорт: *Было: [старое значение]* ➔ *Станет: [распознанное]* + Чекбокс
     - Личный номер: *Было: [старое значение]* ➔ *Станет: [14-значный номер]* + Чекбокс
5. Снимите галочку с одного из полей и нажмите **«Применить выбранные в профиль»**.
6. Перейдите на вкладку **«Профиль»**: убедитесь, что применились только отмеченные поля, а данные зашифрованы в `SecureStorage`.

## Сценарий 4. Связка OCR сканера с каталогом шаблонов

### Цель
Продемонстрировать сквозной перенос текста произвольного отсканированного документа в шаблон Word через буфер `DraftStore`.

### Шаги проверки:
1. На вкладке **«Сканирование»** переключите чип типа документа на **«Любой документ»**.
2. Загрузите любое фото документа с текстом.
3. В нижнем блоке «Распознанный текст» нажмите кнопку **«Перенести текст в шаблон документа...»**.
4. **Ожидаемый результат:**
   - Приложение автоматически открывает вкладку **«Шаблоны»** и выводит уведомление *«Текст готов для вставки в шаблон»*.
   - Выберите любой подходящий шаблон.
   - При открытии шаблона автоматически открывается чат ИИ с уже подготовленным текстом скана: *«Заполни поля документа по тексту: [текст скана]»*.
   - ИИ раскладывает данные скана по полям выбранного шаблона.

## Сценарий 5. Конструктор правил ГОСТ и экспертные панели (`RuleEditorPage`)

### Цель
Продемонстрировать создание и гибкую настройку стандартов оформления ГОСТ без создания дубликатов встроенного правила `MasterRule`.

### Шаги проверки:
1. На вкладке **«Проверка»** нажмите на чип активного правила или на кнопку настройки стандартов оформления.
2. Откроется экран **«Конструктор правил ГОСТ»**.
3. **Ожидаемый результат:**
   - Для главного правила (`MasterRule`) заблокировано случайное переименование, запрещено удаление, а правки сохраняются по месту.
   - Доступны экспертные панели: «Рисунки и схемы», «Листинги программного кода», «Таблицы».
   - В реальном времени отображается интерактивный лист предпросмотра А4 «Было / Стало» (на Android переключение через вкладки «Параметры» / «Лист А4»).
4. Нажмите **«Создать на основе этого»**: введите название собственного стандарта (например, «Стандарт БГТУ»).
5. Отредактируйте параметры и нажмите **«Сохранить»**.
6. **Ожидаемый результат:** Новое правило моментально появляется в чипах на вкладке «Проверка» и готово для аудита документов.

## Сценарий 6. Адаптивность окна, Navigation Rail и Android 15 Edge-to-Edge

### Цель
Продемонстрировать качество верстки на десктопной платформе Windows 10/11 и мобильной платформе Android 15.

### Шаги проверки:
1. **На Windows:** кликните по кнопке-тумблеру **«Свернуть/Развернуть панель»** в левом верхнем углу (над вкладками).
   - **Ожидаемый результат:** Боковая панель плавно сворачивается с 220px до компактных 64px. Область перетаскивания окна мгновенно адаптируется, клики по логотипу и кнопкам не блокируются перетаскиванием окна.
2. Сожмите окно приложения по горизонтали и вертикали до минимальных размеров.
   - **Ожидаемый результат:** Окно аппаратно удерживает минимальный размер 800x600 без вылетов (`WM_GETMINMAXINFO`).
3. Разверните окно на полный экран (1920x1080):
   - **Ожидаемый результат:** Контент центрирован в коридоре 950px с заполнением `Fill` без обрезания контента. Шторка чата открывается аккуратной панелью 490px справа.
4. **На Android:** проверьте отображение приложения на устройствах с Android 15.
   - **Ожидаемый результат:** Благодаря `SafeAreaEdges` системные вырезы камеры, статус-бар и нижняя жестовая панель навигации не перекрывают элементы интерфейса и кнопки действий.
